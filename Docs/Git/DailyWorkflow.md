# 하루 작업 루틴

Git 규칙 중에서 **가장 자주 보게 될 문서**입니다. 다른 규칙을 다 잊어도 이 순서만 지키면 큰 사고는 나지 않습니다.

작업은 GitHub Desktop으로 합니다. 명령어로 하고 싶다면 아래 표의 대응 명령을 쓰면 됩니다.

---

## 작업을 시작할 때

순서를 바꾸면 안 됩니다. 특히 1번과 2번을 건너뛰고 작업을 시작하면 나중에 충돌이 납니다.

1. **`Fetch origin` 을 누릅니다.** 원격 저장소에 무엇이 올라왔는지 확인합니다.
2. **`main` 으로 이동한 뒤 `Pull origin` 을 누릅니다.** 남들이 올린 작업을 내 컴퓨터로 받습니다.
3. **새 브랜치를 만듭니다.** `Branch > New Branch`. 이름 규칙은 `BranchStrategy.md` 를 따릅니다.
4. Unity를 열고 작업을 시작합니다.

<mark>브랜치를 만들기 전에 Unity를 먼저 열지 않습니다.</mark> `main` 상태로 작업하다가 나중에 브랜치로 옮기려면 번거롭습니다.

## 작업하는 동안

- **기능 하나가 동작하면 커밋합니다.** 하루 치를 모아 한 번에 커밋하지 않습니다.
- 커밋 메시지는 `CommitConvention.md` 규칙을 따릅니다.
- 커밋한 뒤 `Push origin` 으로 올려 둡니다. 올려 두면 컴퓨터에 문제가 생겨도 작업이 남습니다.
- 작업이 길어지면 중간중간 `Fetch origin` 으로 다른 사람의 진행을 확인합니다.

## 작업을 마칠 때

1. 남은 변경 사항을 커밋하고 `Push origin` 합니다.
2. 기능이 끝났다면 GitHub에서 **Pull Request를 만듭니다.** 절차는 `PullRequestGuide.md` 참고.
3. 리뷰어를 지정하고 채널에 리뷰 요청을 남깁니다.
4. **작업일지를 씁니다.** `Docs/Members/<이름>/WorkLog/YYYY-MM-DD.md`
5. 작업일지를 커밋하고 푸시합니다.

## PR이 승인된 뒤

1. GitHub에서 `Merge pull request` 를 누릅니다.
2. 이어서 나오는 `Delete branch` 로 원격 브랜치를 지웁니다.
3. GitHub Desktop에서 `main` 으로 이동하고 `Pull origin` 합니다.
4. 다 쓴 로컬 브랜치를 지웁니다. `Branch > Delete`

브랜치를 지우지 않고 쌓아 두면 목록에서 지금 쓰는 브랜치를 찾기 어려워집니다.

---

## 체크리스트

작업 전후로 이것만 확인하면 됩니다.

**시작 전**

- [ ] `Fetch origin` 했는가
- [ ] `main` 에서 `Pull origin` 했는가
- [ ] 새 브랜치를 만들었는가
- [ ] 지금 브랜치 이름이 화면 위에 보이는가

**종료 전**

- [ ] 커밋하지 않은 변경이 남아 있지 않은가
- [ ] `Push origin` 했는가
- [ ] 기능이 끝났다면 PR을 올렸는가
- [ ] 작업일지를 썼는가

## 화면 조작과 명령어 대응

| GitHub Desktop | 명령어 |
|---|---|
| `Fetch origin` | `git fetch` |
| `Pull origin` | `git pull` |
| `Branch > New Branch` | `git switch -c 브랜치명` |
| 브랜치 목록에서 선택 | `git switch 브랜치명` |
| `Commit to 브랜치명` | `git commit` |
| `Push origin` | `git push` |

## 자주 나오는 상황

**작업하다 보니 `main` 에서 하고 있었습니다.**
아직 커밋하지 않았다면 그대로 새 브랜치를 만들면 됩니다. 변경 사항이 따라옵니다. 이미 커밋했다면 혼자 해결하려 하지 말고 강사에게 알립니다.

**브랜치를 바꾸려는데 경고가 뜹니다.**
커밋하지 않은 변경이 있다는 뜻입니다. 커밋하거나, 가져갈지 두고 갈지를 고른 뒤 이동합니다.

**`Push origin` 이 거부됩니다.**
원격에 내가 모르는 커밋이 있다는 뜻입니다. `Fetch origin` 후 `Pull origin` 으로 받아서 합친 다음 다시 푸시합니다. 이때 충돌이 나면 `ConflictPlaybook.md` 를 봅니다.
