# 충돌 대응

충돌은 잘못해서 생기는 것이 아닙니다. **두 사람이 같은 자리를 고치면 Git이 어느 쪽을 남길지 판단할 수 없어서** 사람에게 묻는 것입니다.

중요한 것은 **충돌 대상이 무엇이냐에 따라 대응이 완전히 다르다**는 점입니다. 코드 충돌은 직접 풀지만, 씬 충돌은 풀지 않습니다.

---

## 어떤 파일이 충돌했는지부터 봅니다

| 충돌한 파일 | 대응 |
|---|---|
| `.cs` 스크립트 | 직접 해결합니다 (1번) |
| `.unity` 씬 | <mark>풀지 않습니다.</mark> 씬 소유자에게 넘깁니다 (2번) |
| `.meta` | 어느 에셋이 쓰이는지 확인 후 결정 (3번) |
| 이미지·음원·모델 | 한쪽을 고릅니다 (4번) |
| `.prefab` | 씬과 같게 다룹니다 (2번) |

**어느 경우든, 충돌이 났을 때 시간에 쫓겨 아무 버튼이나 누르지 않습니다.** 잘못 누른 것을 되돌리는 쪽이 훨씬 오래 걸립니다.

---

## 1. 코드 충돌

가장 흔하고, 직접 풀 수 있는 유일한 경우입니다.

충돌한 파일을 열면 아래처럼 표시됩니다.

```
<<<<<<< HEAD
        moveSpeed = 5.0f;
=======
        moveSpeed = 7.5f;
>>>>>>> feature/seunghun_monster-patrol
```

- `<<<<<<< HEAD` 아래: **지금 내 브랜치**의 내용
- `=======` 아래: **가져오려는 쪽**의 내용

**푸는 순서**

1. 양쪽이 각각 무엇을 하려던 코드인지 읽습니다.
2. 남길 것을 정합니다. 한쪽만 남길 수도 있고, 둘을 합쳐야 할 수도 있습니다.
3. <mark>`<<<<<<<`, `=======`, `>>>>>>>` 세 줄을 반드시 지웁니다.</mark> 이 줄이 남아 있으면 컴파일되지 않습니다.
4. 저장하고 Unity 콘솔에 에러가 없는지 확인합니다.
5. GitHub Desktop에서 충돌이 해결된 것으로 표시되면 커밋합니다.

**둘 중 무엇을 남길지 모르겠으면 상대에게 물어봅니다.** 상대가 왜 그렇게 고쳤는지는 코드만 봐서는 알 수 없습니다.

## 2. 씬 충돌과 프리팹 충돌

<mark>씬 충돌은 해결하지 않습니다. 예방하는 것만이 확실한 방법입니다.</mark>

씬 파일은 텍스트로 저장되지만 사람이 읽으라고 만든 형태가 아닙니다. 오브젝트 하나가 여러 덩어리로 나뉘어 번호로 서로를 가리키고 있어서, 한 줄을 고르면 다른 자리의 참조가 어긋날 수 있습니다. Unity가 씬 전용 병합 도구를 따로 만들어야 했던 이유가 이것입니다.

**충돌이 났다면**

1. 아무것도 누르지 않고 채널에 알립니다.
2. 씬 소유자에게 넘깁니다. 소유자는 `ProjectSpec.md` 에 적혀 있습니다.
3. 내가 소유자가 아닌데 내 변경이 들어갔다면, **내 변경을 버리는 쪽이 보통 빠릅니다.** 다시 하는 데 10분 걸릴 작업을 병합하느라 두 시간을 쓰지 않습니다.
4. 판단이 서지 않으면 강사를 부릅니다.

**예방**

- 한 씬은 한 사람만 저장합니다.
- 씬에 직접 배치하는 대신 **프리팹으로 만들어 두면** 그 안의 수정은 씬 파일을 건드리지 않습니다.
- 본인 기능을 시험할 때는 `Assets/Scenes/Test/` 에 본인 테스트 씬을 만들어 씁니다.
- 작업 전에 `Pull` 하고, 마치면 오래 쥐고 있지 말고 올립니다. 부딪힐 시간을 줄이는 것이 예방입니다.

## 3. `.meta` 충돌

`.meta` 파일은 에셋마다 붙는 짝이고, 그 안의 고유 ID로 다른 곳에서 이 에셋을 가리킵니다.

서로 다른 파일을 각자 추가하는 것은 문제가 되지 않습니다. 충돌이 나는 것은 **두 사람이 같은 경로에 같은 이름의 에셋을 각자 추가했을 때**입니다. 이때 양쪽의 고유 ID가 다릅니다.

**한쪽을 지우면 그 ID로 가리키던 연결이 끊어집니다.** 그래서 어느 쪽을 남길지는 그 에셋을 무엇이 쓰고 있는지 보고 정해야 합니다. 정한 뒤에는 Unity 에디터를 열어 인스펙터에서 연결이 살아 있는지(`Missing` 표시가 없는지) 확인합니다.

혼자 판단하기 어려우면 강사를 부릅니다.

## 4. 이미지·음원·모델 충돌

이런 파일은 애초에 합칠 방법이 없습니다. **한쪽을 골라야 합니다.**

그래서 처음부터 담당자를 정해 두는 편이 낫습니다. 같은 텍스처를 두 사람이 각자 고치는 상황 자체를 만들지 않습니다.

---

## 강사를 부르는 기준

아래는 혼자 처리하지 않습니다.

- 씬 파일이나 `.meta` 파일 충돌
- 어느 쪽을 남겨야 할지 판단이 서지 않는 경우
- 충돌을 풀다가 프로젝트가 열리지 않게 된 경우
- 무언가를 되돌리고 싶은데 어떤 버튼인지 모르는 경우

**되돌릴 수 있는 상태에서 부르는 것과, 여러 번 눌러 본 뒤에 부르는 것은 복구 난이도가 다릅니다.** 이상하다고 느낀 시점에 부르는 것이 가장 빠릅니다.
